## 2. 已确认定位

> 面向微信群熟人场景的轻量商品接龙工具。系统负责商品展示、订单记录、自动统计和清单输出；不接管资金和履约。

这里使用“接龙”而非“拼团”：当前需求没有提到最低人数、最低金额或未达门槛失败，因此暂不把成团规则加入产品。

## 4. 商品发布边界

平台允许用户发布一般合法商品的接龙信息，不参与定价、收款和履约。平台不保证事前掌握每件商品，但必须提供规则、检测、举报及下架能力。

第一版负面清单至少包括：药品、医疗器械、烟草、电子烟、酒类、保健品、危险品、色情或赌博相关商品、非法票券、侵权商品，以及依法或依微信规则需要特殊资质而发布者无法证明资质的商品。

后续如开放食品、酒类等受限类目，应先补充发布者资质审核和对应服务类目，不默认开放。

## 6. 已识别的风险

| 风险 | 影响 | 当前处理方向 |
|---|---|---|
| 把接龙误做成完整电商 | 范围、资质和开发成本显著增加 | 坚持首版不处理资金与履约 |
| 微信登录等同于获得用户资料 | 无法实现或违反授权规则 | 登录身份、昵称和头像分别设计；电话只在收货信息中由用户填写 |
| 公开接龙名单泄露个人信息 | 隐私与信任风险 | 字段最小化、分角色授权、敏感字段默认隐藏 |
| 商品文字和图片违规 | 审核及运营风险 | 内容安全检测、举报与处置流程 |
| 直接连接打印机 | 机型和协议导致范围失控 | 先生成标准清单文件或页面 |
| 截止与提交并发 | 数据统计不一致 | 使用服务端时间、事务和幂等策略 |
| 取消活动与接龙操作并发 | 出现活动已取消但订单仍生效等不一致 | 由服务端在同一业务事务中校验活动最终状态 |
| 发布后修改商品 | 历史订单金额失真 | 明细保存提交时价格快照，改价不影响已提交订单；改价须二次确认并记录前后值；有历史明细的商品禁止删除 |
| 重复点击或网络重试 | 把请求重试误建为新订单，造成重复订单或重复扣减库存 | 每次明确的新下单意图使用独立幂等键，同一次请求重试复用幂等键，并以订单号唯一约束兜底 |
| Excel 公式注入 | 打开清单时执行恶意公式或泄露数据 | 所有用户可控文本按普通文本安全写入，禁止成为可执行公式 |
| 清单下载链接泄露 | 姓名、电话和地址等敏感信息外泄 | 每次下载校验团长权限，使用不可公开枚举的短期地址并在过期后失效 |
| 没有运营后台也没有处置能力 | 无法应对投诉或违规 | 架构阶段设计最低限度内部运营能力 |
| 个人或个体工商户主体类目不匹配 | 无法提审或正式上线 | 开发前核验；必要时使用公司主体或收缩功能 |
| 过早追求跨平台 | 首版复杂度增加 | 业务规则与微信能力解耦，但首版只实现微信 |
