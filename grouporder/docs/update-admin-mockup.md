## 0. 为什么要修订

v2 画于 **9-17 19:11**，D-072 定于 **9-18**。v2 全文 `D-072` 出现 0 次、`D-068` 出现 4 次——它完整实现了一套**已被推翻**的敏感数据治理机制：默认脱敏、二次验证、受控解敏、导出限制。

D-072 的原文结论：

> 运营后台**不做任何数据脱敏**，也**不设二次验证与受控解敏机制**。全部页面直接展示完整的收货人姓名、电话、地址及订单明细；查看不需要关联处理事项、不需要填写原因、不限制访问范围。**导出完全放开**。删除类操作以输入 `delete` 的二次确认弹窗防误操作。
> 理由：运营后台面向平台内部，运营人员本就是这些数据的合法持有方；为单人或极小规模团队建设一整套内部防越权机制，成本与收益不成比例。

**取消脱敏不等于取消约束。** 约束换了一种形式，v3 必须把这一点画出来：原来靠「看不见」来防，现在靠「看得见但全记录」来防。以下三条不受影响，继续有效：

1. **运营不得代替团长经营**（OPS §2.2）——原红线③
2. **审计日志不可修改或删除**（OPS §13）——原红线⑦
3. **Excel 公式注入防护**（D-039）——防的是用户在备注里埋公式，与隐私无关

| ② | 业务状态与治理状态必须并列，不能合并 | ✅ 保留，原文不动 |
| ③ | 运营不得代替团长经营 | ✅ 保留，原文不动 |
| ④ | 二次验证不是登录 | ❌ **作废**（D-072） |
| ⑤ | 统计指标只能用白名单里的词 | ✅ 保留，原文不动 |
| ⑥ | 菜单按权限展示 | ✅ 保留，原文不动 |
| ⑦ | 审计日志不可修改删除 | ✅ 保留，原文不动 |
| ⑧ | Excel 审计不提供下载 | ❌ **作废**（D-072） |

**编号不重排**，①④⑧ 留空缺。理由同 A-11：重排会让所有既有图注的角标失效，且与其他文档的交叉引用对不上。

### 新增一条红线⑨

> **⑨ 不脱敏，但每一次查看和导出都必须入审计**
>
> D-072 取消脱敏，约束并没有消失，只是换了形式：原来靠「看不见」来防，现在靠「看得见但全记录」来防。v3 里凡是展示完整姓名、电话、地址的屏（A-04、A-06、A-07、A-12、A-13、A-16），图注都要点明这一次访问会入审计。
>
> 画成「既不脱敏也不提审计」是本次修订最容易犯的错——那等于把 D-072 读成了「运营后台对数据没有任何约束」，而 D-072 的原文恰恰把审计链路完整保留了下来。
>
> 日志本身仍然**不记录密码等凭证，也不记录可继续使用的下载地址**（D-071③）。
