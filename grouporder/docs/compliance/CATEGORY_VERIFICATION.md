## 2. 为什么必须核验

本产品的实质形态是：**任何用户都可以发布带价格和库存的商品，其他用户下单登记，线下交收**。

评审 B-01 判断这条路线「大概率不成立」，冲突点在于：

- 这个形态在微信的类目体系里最接近**电商平台**
- 而电商平台类目通常要求**企业主体** + 《增值电信业务经营许可证》(EDI)
- 个人与个体工商户主体一般够不到该类目

若判断成立，产品要么换公司主体，要么收缩形态。这是唯一可能推翻整个项目的风险，因此必须在投入大量开发工时前拿到结论。

## 3. 核验步骤

### 步骤 1：注册一个小程序，只为查看类目列表（约 30 分钟）

个人主体小程序**免费且即时通过**，注册它与将来用什么主体上线、何时上线**完全无关**。目的只是打开后台看到真实的可选类目。

```
weixin.qq.com/cgi-bin/wx → 注册 → 选择「小程序」→ 个人主体
```

### 步骤 2：查看可选类目与资质要求

```
mp.weixin.qq.com 登录
  → 设置 → 基本设置 → 服务类目 → 添加/修改类目
```

该页面会按你的实际主体类型，列出**全部可选类目**及**每个类目所需的资质材料**。这是唯一权威答案，比任何官方文档和第三方教程都准确。

**把这个页面截图保存**，作为本次核验的证据。

### 步骤 3：对照候选类目逐项确认

| 候选类目 | 与本产品的匹配度 | 需确认 |
|---|---|---|
| **电商平台** | 最匹配产品实质 | 个人/个体户能否选？是否要求 EDI？ |
| 商家自营（各细分） | 不匹配 | 该类目设定为「经营者销售自有商品」，与「任何用户均可发布」的平台形态冲突 |
| 工具 / 效率 | 勉强 | 若定位为「接龙登记工具、不涉及交易」或可行，但**审核看实际功能**，存在价格、库存、下单即易被判为电商，属高风险选择 |
| 社交 / 社区 | 勉强 | 同上 |

### 步骤 4：后台看不明确时直接询问

渠道：小程序后台在线客服 / 工单，或微信开放社区提问。

**提问话术（可直接复制）**

> 我的小程序功能是：微信群成员可以发起商品接龙，填写商品名称、价格、库存；其他成员选择数量提交登记，系统自动汇总并生成清单。**平台不提供在线支付功能，不参与商品交付**，收款和交付均由用户在线下自行完成。**活动不进入任何公开列表，也不提供发现、推荐、搜索或分类，只能由发起人主动分享给特定微信群或好友后才能访问。**请问这个功能应当选择哪个服务类目？是否需要《增值电信业务经营许可证》？个人主体（或个体工商户主体）能否使用该类目？

> **「不提供在线支付、不参与交付」与「无公开列表、仅分享进入」是本产品最重要的两条论据**，务必写入询问，它们是整个类目论证的支点。前者由 D-005 确定，后者由 D-059 确定——没有公开列表意味着产品不具备撮合陌生交易的平台特征，这对类目判定可能是有利事实，但**最终以微信答复为准，不得据此自行放宽**。
