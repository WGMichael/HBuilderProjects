- 文档状态：待主控、产品负责人、产品审查评审
- 适用产品版本：PRD v1.1
- 配套文档：`UX_STATE_MATRIX.md`、`UX_REVIEW_GATE.md`

## 1. 文档目的与边界

本文定义微信小程序端与平台运营后台的页面信息架构、页面职责和端到端任务流，供后续低保真原型、架构与开发拆分使用。

本文不定义视觉风格、组件皮肤、技术接口、数据库结构或事务实现。订单三年保存、账号存续期间保存及注销后限制处理按已确认产品规则呈现；Excel、举报/审计记录和备份等尚未确认的具体期限不在本文中自行定义。页面遇到并发或状态冲突时，以服务端返回的最终状态为准；具体幂等、鉴权和原子处理方式交由架构阶段设计。

首版明确不提供在线支付、退款、采购、配送、物流、核销、售后、订阅消息、团长代参与者补录、活动密码、参与审核、团长 Web 管理后台、运营统计导出或运营后台 Excel 下载。

## 2. 角色与术语

- 平台用户：通过微信授权或用户名密码进入的统一用户身份。
- 团长：某次活动的创建者，仅在该活动中拥有团长权限。
- 参与者：在活动中提交本人订单的平台用户。
- 收货信息：用户维护的一条姓名、电话和完整地址，可设置默认项。
- 收货快照：订单提交时复制并保存的完整收货信息；地址簿后续修改或删除不影响快照。
- 内容运营：处理举报、内容复核、活动下架/恢复和发布者处置。
- 账号与隐私专员：处理绑定申诉、注销事项及按事项受控查看敏感资料。
- 审计查看者：只读查询完整审计轨迹。
- 超级管理员：创建、停用运营账号并分别分配角色；不自动拥有业务、敏感或统计权限。
- 运营统计查看：独立且默认关闭的权限，不随任何角色自动获得。
- 活动业务状态：草稿、审核中、进行中、已截止、已取消。
- 活动治理状态：正常、已下架；商品另有独立治理下架状态，与团长主动停售分开记录。

## 4. 小程序端主流程

### F-M01 双登录、注册与访问承接

- 入口：大厅任一 tab、微信分享进入 M-13、任一受保护动作。
- 正常路径：M-02 选择微信授权或用户名密码；成功后回到触发登录的原页面和原任务。平台注册走 M-04，注册不要求手机号，并明确未绑定微信时首版无法自动找回密码。
- 失败/返回：拒绝微信授权时保留 M-02 的用户名密码入口；密码错误停留 M-03；弱网允许安全重试；返回时不丢失可安全保留的未提交表单。
- 终态：进入统一平台用户；未登录可以浏览 M-13 的非敏感内容，但不能提交订单、管理活动或查看本人历史。

### F-M02 微信绑定与密码重设

- 入口：M-05 或 M-03 的微信验证重设密码。
- 正常路径：平台账号登录后发起绑定；展示当前平台账号和待绑定微信；确认后一对一绑定。绑定成功后两种登录方式进入同一平台用户。已绑定账号经微信身份验证进入 M-06 重设密码。
- 失败/返回：微信或平台账号已绑定其他身份时展示冲突；双方均已有业务数据时明确“不合并、不直接绑定、不提供申诉解决”，只保留两个原账号各自登录入口；未绑定微信的账号不展示虚假的自动找回能力。M-07 只处理不涉及两个业务账号合并的其他绑定异常。
- 终态：绑定成功、密码重设成功、维持原账号、或申诉已提交。

### F-M03 团长创建、审核与发布

- 入口：「发起接龙」tab（新建态）、M-09 草稿（编辑态，非 tabBar 页）。
- 正常路径：登录 → M-10 填活动资料和截止时间 → M-11 添加一个或多个商品 → M-12 预览 → 提交发布审核 → “审核中” → 团长从 M-09/M-20 查看进度 → 审核通过后进入“进行中”并开放分享。活动不进入任何公开列表，仅通过团长主动分享的入口进入（D-059）。
- 失败/返回：必填缺失定位字段；截止时间无效阻止提交；图片失败可重试；审核不通过退回草稿并展示原因；审核中可撤回至草稿但不能直接修改；结果未知时先查询审核状态，不重复创建活动。
- 终态：草稿、审核中，或形成唯一的进行中活动分享入口（不进入公开列表）。

### F-M04 浏览、选择与创建首张订单

- 入口：持有效入口的微信用户通过分享卡片进入，或从 M-18、M-13 进入；入口不授予任何敏感数据权限。
- 正常路径：游客浏览非敏感内容 → 选择商品数量 → 受保护动作触发 M-02 → 回到 M-13 → M-14 核对商品、全部有效订单累计限购余量和预计金额 → **送货上门活动**进入 M-15 选择一条收货信息，**自提活动**就地填写或选择收货人姓名与电话、不进入地址簿（D-060） → 提交 → M-17。
- 失败/返回：活动审核中、不存在、已截止、已取消或已下架进入 M-26；有限库存或限购变化时保留仍有效选择并提示调整；商品停售或治理下架后不可新增选择；全部商品不可购买时显示明确空态；返回 M-13 时不自动提交。
- 终态：单张有效订单创建成功，或明确未创建。

### F-M05 收货信息维护与订单快照

- 入口：M-08 或 M-14 → M-15。
- 正常路径：查看多条完整收货信息 → 选择默认项或其他项；需要时进入 M-16 新增/编辑 → 保存后返回 M-15 并明确选择 → M-14 提交。每张订单只选一项并保存姓名、电话、完整地址快照。
- 失败/返回：姓名、电话、完整地址缺失或格式不满足必要校验时就地提示；保存失败保留输入；删除地址簿记录前说明不影响历史订单快照。删除默认项后自动把剩余记录中创建时间最早的一条设为默认；无剩余记录时显示空地址簿。
- 终态：地址簿变化成功，或一条收货信息被本次订单明确选中。电话不用于登录、绑定或身份核验。

### F-M06 多订单、“再下一单”与单单管理

- 入口：M-17“再下一单”、M-18 活动下订单列表、M-19。
- 正常路径：“再下一单”创建新的下单意图并回到 M-13/M-14；每次明确操作可生成新订单。M-18 展示同一活动下多张订单；M-19 可修改目标订单的商品明细、数量、收货信息和买家备注，或取消目标订单。
- 失败/返回：重复点击或同一次弱网重试只查询/返回原请求结果，不生成额外订单；修改时按用户全部有效订单合计校验有限限购；移除全部明细时提示取消订单，不保存空订单；取消只影响目标订单并释放其有限库存占用。
- 终态：新订单创建成功、目标订单修改成功、目标订单已取消，或原状态保持。取消记录保留；活动仍进行时可再次明确“再下一单”。

### F-M07 团长查看统计与订单明细

- 入口：M-09 → M-20 → M-21。
- 正常路径：查看业务状态和治理状态 → 有效订单数、有效总份数、预计金额 → 商品汇总/参与者履约明细。各商品已购买份数按其有效明细数量之和计算，有效总份数为各商品之和，有效订单数按订单张数单独计算；预计金额使用有效明细价格快照乘数量。
- 失败/返回：统计加载失败显示重试；数据有延迟时显示统计时间/截至时间；权限或活动归属变化时停止展示并返回 M-26。
- 终态：完成只读核对或进入商品、截止、取消、清单任务。页面不得称“销售额”“实收”或“实际成交”。

### F-M08 商品管理、历史锁定、停售与恢复

- 入口：M-20 → M-22。
- 正常路径：活动截止前可新增商品；从未产生成功明细的商品可自由改价或删除；曾产生成功明细的商品可改价（二次确认并提示已提交订单按原价保留）但不可删除，可停售；进行中且未截止时可恢复停售商品。单位默认“份”，`total_stock=0` 表示库存不设上限，`per_user_limit=0` 表示不限购。
- 失败/返回：有限总库存不得调低至该商品的已购买份数以下；与订单提交、截止、取消或下架竞争时展示服务端最新业务/治理/商品状态；重复停售/恢复返回当前状态。停售商品禁止新增或增加，但允许已有订单减少、移除、更换收货信息、修改备注或取消。
- 终态：商品信息更新、删除、停售、恢复，或保持服务端最终状态。已有订单和历史清单记录不因停售而删除；全部商品停售或售罄时活动仍为进行中并显示暂无可购买商品。

### F-M09 手动截止、自动截止与团长取消

- 入口：M-20 → M-23；自动截止由到时后的状态刷新触发。
- 正常路径：手动截止展示立即禁止新增/修改/取消的影响并确认；自动截止直接呈现“已截止”；取消草稿或进行中活动需二次确认，进行中还需填写取消原因，成功后不可恢复。
- 失败/返回：提交过程中若状态已变化，展示最新业务状态；取消或截止与订单操作竞争时以服务端结果为准；用户返回则不执行。
- 终态：已截止或已取消。两者均为业务状态，不能与运营“已下架”互换；已取消活动展示取消前统计快照和历史订单，但不进入当前有效统计，也不产生有效履约清单。

### F-M10 清单预览、Excel 生成与下载

- 入口：已截止活动 M-20 → M-24。
- 正常路径：查看同一数据时点的商品汇总和参与者明细 → 发起 Excel 生成 → 显示生成中 → 成功后请求下载 → 再次校验当前团长权限 → 使用短期地址下载。
- 失败/返回：生成失败允许重试；团长作废整张订单时必须填写原因且不可恢复，作废导致清单版本变化并标记需刷新/重新生成；下载链接过期、被转发或权限变化时拒绝并提示重新获取或返回活动；结果未知先查询生成状态。
- 终态：下载成功、生成失败、链接过期或权限拒绝。文件至少含“商品汇总”和“参与者明细”；商品汇总每个商品一行，参与者明细每条商品明细一行并重复必要的订单及收货字段；所有用户可控文本必须按普通文本安全写入，不能成为可执行公式。

### F-M11 举报与结果查看

- 入口：M-13 举报入口、M-08 反馈/举报记录。
- 正常路径：M-25 选择活动或单个商品、填写举报内容 → 提交唯一举报 → 查看处理中/结案/复核结果。提交举报不会立即下架；运营审核成立后才下架被认定违规的单个商品或整个活动。
- 失败/返回：弱网或重复提交先查询原举报结果；活动已下架仍可展示适当状态；内部证据、审核备注和敏感材料不向用户展示。
- 终态：举报已提交、已结案或复核完成。首版不发送订阅消息或主动微信通知。

## 5. 运营后台主流程

### F-A01 登录、角色导航与权限变化

- 入口：A-01。
- 正常路径：运营账号登录 → 校验启用状态和当前角色 → A-03 仅展示获权导航。敏感查看前进入 A-02 二次验证；统计入口仅在独立统计权限存在时展示。
- 失败/返回：账号停用、权限不足、会话或二次验证失效分别反馈；权限撤销后已开页面的下一次操作立即拒绝并隐藏敏感内容。
- 终态：进入授权工作台，或拒绝访问并留下审计结果。

### F-A02 检索与只读运营统计

- 入口：A-03 → A-04/A-05。
- 正常路径：按稳定内部标识检索；统计权限用户按今天、近 7 天、近 30 天或自定义时间查看团长汇总 → A-06 下钻活动与商品。展示统计时间/截至时间。
- 失败/返回：无统计权限不展示入口且直接访问被拒；无结果显示空态；日期无效指出具体问题；汇总未完成显示未知/延迟，不用零值代替。
- 终态：只读查看脱敏摘要或非敏感汇总。指标仅使用已发布活动数、有效订单数、有效总份数、预计金额；不得修改、校正或批量导出。

### F-A03 发布审核、举报审核、复核与结案

- 入口：A-03 待办、A-08、A-04。
- 正常路径：领取发布审核或举报 → 查看待发布/被举报内容快照、检测记录和历史处置 → 发布审核选择通过或不通过；举报审核选择无违规、警告、下架单个商品、下架活动或发布限制并填写理由 → 提交时重验权限与状态 → 结案；需要时创建新的复核记录。
- 失败/返回：状态被他人改变时显示最新处理人和可公开原因；重复请求返回当前结果；返回不覆盖原证据或结论。
- 终态：已结案、复核中或复核完成，所有轨迹保留。

### F-A04 商品/活动下架与恢复

- 入口：A-07/A-08 → A-09，仅内容运营。
- 正常路径：同时展示活动业务状态、活动治理状态和商品治理状态 → 审核认定举报成立后选择下架单个商品或整个活动，填写原因并确认影响 → 提交；恢复必须有允许恢复的复核结论，并在提交时重读相关状态和发布限制。
- 失败/返回：已截止、已取消或下架期间到期时不能恢复为可参与；重复操作返回当前状态；权限/状态变化阻止旧页面覆盖新状态。
- 终态：目标商品或活动的治理状态为已下架或正常。单商品下架不影响其他正常商品继续参与；治理下架不改变活动业务状态，不删除订单、商品、快照或历史清单。

### F-A05 发布者处置

- 入口：A-07/A-08 → A-10，仅内容运营。
- 正常路径：查看当前发布限制 → 选择警告、临时限制、永久限制或解除限制 → 填写原因并确认 → 提交时重验。
- 失败/返回：相同状态重复操作不重复生效；并发变化展示最新状态。
- 终态：警告记录，或发布权限变为正常/临时限制/永久限制。限制只影响创建或发布活动，不影响登录、历史查看和参与他人活动。

### F-A06 敏感资料受控查看

- 入口：A-04/A-12/A-16 → A-11，仅账号与隐私专员。
- 正常路径：关联已分配的有效事项 → 填写具体原因 → A-02 二次验证 → 重验事项、对象范围和权限 → 只展示必要的完整姓名、电话、地址。
- 失败/返回：无事项、无权限、验证失败/过期、对象越界均拒绝并审计；页面重开、会话失效、账号停用或权限撤销后立即隐藏完整字段。
- 终态：当前事项最小范围解敏或访问拒绝。不得批量导出、复制清单或下载 Excel。

### F-A07 账号绑定申诉

- 入口：A-03/A-04 → A-12。
- 正常路径：查看脱敏摘要 → 记录身份核验 → 检查当前绑定、一对一约束和双方业务数据 → 符合条件时解绑/重新绑定，否则拒绝 → 用户在 M-07 查看结果。
- 失败/返回：双方已有业务数据时直接终止处理，不受理申诉解决，也不得合并或迁移；收货电话不得用于身份核验；其他重复或并发请求返回最新关系，不覆盖新绑定。
- 终态：处理成功或处理失败，前后关系、原因、操作人和结果可审计。

### F-A08 Excel 与审计日志

- 入口：A-13/A-14。
- 正常路径：按活动、团长、时间和结果查询 Excel 事件；按操作人、对象、事项、动作和时间查询授权范围内日志。
- 失败/返回：无权、对象不存在或查询失败分别反馈；日志中的临时地址、密码和验证凭证不可见。
- 终态：只读查看事件摘要。任何运营角色均不能预览、下载或重新生成团长清单，也不能修改或删除日志。

### F-A09 运营账号和权限管理

- 入口：A-15，仅超级管理员。
- 正常路径：创建运营账号 → 分别授予角色及独立统计权限；可停用账号或撤销单项权限 → 显示变更结果。
- 失败/返回：不能自助注册、自行提权或修改自己的角色；超级管理员未兼任时不得进入业务处置、敏感查看或完整审计。
- 终态：账号启用/停用及角色变化即时生效并可审计。

### F-A10 注销、删除与匿名化事项

- 入口：A-03/A-04 → A-16，仅账号与隐私专员。
- 正常路径：登记事项 → 身份核验 → 检查本人审核中/进行中活动及尚未截止/取消活动中的有效订单 → 存在任一项时阻止注销并列出需先处理的对象 → 条件满足后区分账号/地址簿与订单资料 → 注销后删除或匿名化账号资料和当前地址簿 → 尚在三年期内的订单资料转为限制处理 → 从活动截止或取消起满三年后删除或匿名化订单个人字段和账号关联 → 记录处理结果。匿名汇总可以长期保留。
- 失败/返回：保存起点或到期状态不明确时停止执行并进入复核；部分处理失败不得显示整体成功。Excel、举报/审计记录和备份等仍未确认的期限不得自行承诺。
- 终态：事项已登记、处理中、限制处理、到期处理成功或处理失败；所有操作可审计。

## 6. 全局导航与返回原则

- 登录完成后返回原任务，不强制回大厅。
- **分享卡片进入是单页启动**：用户从群卡片直达 M-13 时页面栈深度为 1，`navigateBack` 会失败。左上角返回必须判断 `getCurrentPages().length === 1` 则 `switchTab` 到「接龙」tab，否则 `navigateBack`。这是微信小程序的技术事实，不是产品选择。
- **tabBar 页只能用 `switchTab` 进入且不能带参数**：因此「发起接龙」tab 恒为 M-10 的**新建态**，编辑草稿必须是另一个非 tabBar 页面，从 M-09 列表 `navigateTo` 进入。
- 点「发起接龙」tab 时若已存在未提交草稿，表单保持新建态，顶部显示一条「你有 N 个未完成的接龙草稿，继续编辑 / 忽略」提示条，**不强制跳转到草稿**（产品负责人 2026-09-15 确认）。
- **tabBar 最多 5 项**，当前 3 项；中间「发起接龙」的凸起圆形入口需自定义 tabBar 组件实现，不能用原生配置，`setTabBarBadge` 相应改为自定义组件的状态管理。
- 「接龙」tab 显示未关闭的优先级 1–2 待办数量角标。首版不做订阅消息（D-032），这是让用户「回来就看见」的唯一手段。
- “再下一单”是唯一表达新增订单意图的主动作；页面刷新、返回重进和重试不得等价为新增订单。
- 从 M-14 进入收货信息管理后，返回仍需明确选中某条信息，不能因编辑自动提交订单。
- 活动页始终并列呈现业务状态与治理状态；截止、取消、下架分别解释。
- 任何写操作结果未知时，优先进入查询/刷新结果，不直接鼓励重复提交。
- 高风险或不可逆动作必须显示对象、影响范围、原因字段（规则要求时）和二次确认。
- 运营后台菜单和页面操作随当前权限展示；隐藏入口不能替代服务端最终鉴权。
